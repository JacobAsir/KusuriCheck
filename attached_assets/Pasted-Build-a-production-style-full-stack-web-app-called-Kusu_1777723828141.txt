Build a production-style full-stack web app called “KusuriCheck”.

High-level goal:
KusuriCheck is a Japan-first utility AI app that helps users understand Japanese medicine and supplement information more clearly.
A user uploads or scans a Japanese OTC medicine package, supplement label, or pharmacy instruction sheet, and the app explains the content in simple Japanese and English.

Important safety boundary:
This app is NOT a doctor, pharmacist, diagnosis tool, or treatment decision engine.
It must never provide medical diagnosis, emergency advice, or personalized prescribing decisions.
It must present itself as an assistive medicine-information reading tool only.
When risk is high, uncertainty is high, or the content suggests prescription-only or serious warning information, the app should clearly tell the user to consult a pharmacist or doctor.

This version should be stateless.
Do NOT use any database, authentication, or Supabase.
Do not add login, user accounts, saved history, cloud storage, or persistent profiles.
All analysis should happen per request.
Temporary file handling only.

Primary user problem:
Japanese medicine labels, package inserts, and instruction sheets are often dense, formal, and difficult to understand quickly.
Users need simple, trustworthy explanations of usage, timing, warnings, and red flags in plain Japanese and English.

Target users:
- Japanese consumers buying OTC medicines
- Foreign residents in Japan
- Travelers in Japan carrying or buying medicines
- People checking supplement labels
- Caregivers helping older family members read medicine instructions

Non-goals for MVP:
- Do not provide diagnosis
- Do not recommend treatment plans
- Do not calculate full medical safety or interaction certainty
- Do not replace pharmacists or doctors
- Do not add database or auth
- Do not support advanced clinical workflows initially
- Do not overbuild agents in v1

Required product behavior:
The user uploads or captures a photo of:
- an OTC medicine box
- a supplement label
- a pharmacy instruction sheet
- a medicine leaflet or insert section

The app:
1. validates the file
2. temporarily processes the image or document
3. extracts Japanese text
4. identifies important sections such as intended use, dosage/use timing, warnings, age restrictions, and caution phrases
5. detects whether the content appears OTC, supplement-related, or higher-risk prescription-like content
6. produces a consumer-safe explanation
7. returns:
   - what it appears to be
   - what it is generally used for (only if supported by extracted text)
   - how to use it (only if explicitly stated)
   - key warnings
   - when to ask a pharmacist or doctor
   - Japanese and English summary
   - evidence from extracted text
8. does not store the upload permanently

Analysis pipeline requirements:

Step 1: File intake
- validate file type and size
- basic image quality checks if possible
- temporary memory or temp-file handling only
- cleanup after processing

Step 2: OCR / extraction
- Build OCR provider abstraction
- Support:
  - mock provider
  - Gemini-based extraction provider
- Normalize extracted text into a consistent schema
- Return extracted blocks / lines if possible

Step 3: Document classification
Classify the input into:
- OTC medicine
- supplement
- instruction sheet
- package insert fragment
- unclear
Use deterministic heuristics first, then optional model assistance

Step 4: Structured parser
Extract if present:
- product name
- intended use / indication-like text
- dosage / administration wording
- age restrictions
- warning phrases
- pregnancy / child / elderly caution references
- storage instructions
- ingredients / active ingredients if visible

Step 5: Rule engine
Implement deterministic safety-first rules.
Examples:
- If the text contains strong warning markers or boxed-warning-style phrasing, elevate caution
- If usage instructions are incomplete or confidence is low, do not summarize aggressively
- If prescription-like warning structure appears, mark as higher-risk and recommend pharmacist/doctor confirmation
- If the extracted text includes caution for pregnancy, children, elderly, liver, or kidney use, surface it prominently
- If the app is uncertain, prefer “Consult pharmacist” over confident interpretation

Step 6: Optional LLM explanation layer
- Use Groq LLM to convert structured findings into plain-language bilingual summaries
- Must never invent unsupported uses, dosages, or safety claims
- Must stay grounded in extracted evidence
- If LLM fails, use deterministic template summaries

Step 7: Decision / guidance output
Return a structured output that includes:
- content type
- confidence score
- extracted sections
- warnings
- consult recommendations
- summary_ja
- summary_en
- evidence lines
- raw OCR text
- processing_mode
